# Steps 6–8 — UNR Result Review, IMC Merge, Exclusion and Refinement (formal-unr)

- Used by SKILL.md Steps 6, 7 and 8.
- Doc basis: D1 "Generating a Coverage Database", "Converting Unreachable to Excluded in IMC", Appendix A; D2 `check_unr -list`, `-reason`; D7 `exclude`, "Excluding Unreachable Items", `save`, `load`, `report_metrics`, Launching IMC.
- Core rule (D1): UNR marking does NOT change the coverage score; only reviewed items converted to Exclude do. Never exclude without review.

## 1. Result Categories

| Jasper status (`check_unr -list`, D2) | Meaning | Action |
|---------------------------------------|---------|--------|
| `UNR` unreachable | proven unreachable under the run constraints | review (§3) → exclude with comment, or report as finding |
| `RCH` reachable | a stimulus exists | keep as hole → test-writing input (witness with `-keep_trace`) |
| `BND` bounded | no conclusive result in the time/effort given | keep as hole; Step 9 (undetermined handling) |
| `UNP` unprocessed | not processed (e.g. time-out before the chunk ran) | re-run (Step 9) |
| `DSB` disabled | target disabled by the user | justify each disable in the run summary |
| `discarded_items_report.txt` (session dir) | sim holes that could not be evaluated + reason (D2 `-setup`) | review; stay holes; list in the summary |

| IMC marker (D7) | Meaning | Rule |
|-----------------|---------|------|
| red, Fully Unreachable (`F_UNR`) | all items in the instance/type unreachable | per-item review still required |
| orange, Partially Unreachable (`P_UNR`) | only some items unreachable | NEVER exclude at this level (D1) — open and exclude items individually |
| gray, Excluded Unreachable (`U-EXCL`) | UNR item converted to excluded | must have a comment and an `unr_review.csv` row |

## 2. Open the Merge

- Merge script (D1/D6): `<jgproject>/sessionLogs/session_<n>/unr_imc_coverage_merge.cmd` (partitions: main session `session_0`, partitions `session_1..`, D1).
- Read the script BEFORE running it (kit README step 4): record the sim DB path, the UNR DB path (`<covwork>/<covscope>/<covtest>`, covtest default `unr`), and every `exclude` / `save -refinement` line. Its exact content is generated by the tool — UNCONFIRMED beyond the D6 README ("uncomment the exclude line ... save -refinement").
- Keep the generated blanket `exclude ... -unr` line COMMENTED (K10).
- GUI review: `imc -nostdout -init <merge.cmd>` (D7: `-init` runs the file at session start; `-nostdout` suppresses summary messages).
- Batch: `imc -exec <script>` (D7: runs and exits).
- In the GUI: add the "Overall UNR" / "Overall Local UNR" columns (D1 Example 1) and filter the UNR column (Fully / Partially Unreachable, D7).

## 3. Per-Item Review (MANDATORY before any exclusion)

- One row per UNR item in `<results>/unr_review.csv`:
  - Columns: `UNR_ID,Type,Instance,Item,Source_Line,Jasper_Property,Reason_File_Cause,Classification,Justification,Spec_Ref,Constraint_Dependency,Decision,Reviewer,Date`.
  - `Type`: block / expression / toggle / fsm / functional.
  - `Jasper_Property`: D1 naming (`block_cov_line_<n>_<col>`, `expr_cov_line_<n>_<col>`, `toggle_cov_<sig>_{rise|fall}`, `fsm_cov_reach_<fsm>_<state>`, `fsm_cov_tran_<fsm>_<from>_<to>_arc<id>`).
  - `Reason_File_Cause`: from `unr_reason.txt` (`check_unr -reason`, App. A: constant or propagated-assume causes only); empty if not listed.
  - `Constraint_Dependency`: none / reset choice / `asm_unr_<name>` / inst_top port constant / black box / resilient-compilation removal.
  - `Decision`: EXCLUDE / FINDING (RTL) / FINDING (constraint) / KEEP-HOLE / ASK-USER.
- Classification (RTL is read here only to UNDERSTAND the item; the verdict needs the spec):

| Class | Typical cause | Decision |
|-------|---------------|----------|
| C1 Structural dead code | constant-driven logic, unused parameter branch, default of a full case, tied input in the IP itself | EXCLUDE if the spec does not require the behaviour; comment cites the cause |
| C2 Spec-unused mode / config | feature disabled by a spec-fixed parameter or pin for this configuration | EXCLUDE per config only; Spec_Ref mandatory; NOT valid for other configs |
| C3 Constraint-induced | item unreachable only because of `assume`, reset choice, inst_top port constant | EXCLUDE only if the constraint has a spec reason AND holds in every integration; else FINDING (constraint) |
| C4 Spec says reachable | spec describes behaviour that maps to this item | FINDING (RTL bug or spec gap) — do NOT exclude; `formal-cex-debug` / ask user |
| C5 Tool / model artefact | enum-X semantics, formalbuild optimisation, sim-only code, resilient-compilation removal (D1 Limitations) | KEEP-HOLE or ASK-USER; never silently exclude |

## 4. Validity Rules for Exclusions

- A UNR verdict is valid ONLY under the stated constraints, reset/initial state, `-inst_top`, black boxes and coverage options of that run.
- Under-approximations (can create FALSE unreachables — every one needs a spec reason):
  - `assume` / mode tie-offs; `reset` state choice (R1/R3 vs un-initialised R2); constants on the `-inst_top` ports preserved from the TB (D1) — the TB tie-off may differ in the SoC integration.
  - Embedded SVA assumes enabled with `-enable_assumption` / `-jg_unr_assumption`.
- Over-approximations (sound for UNR; may leave true-UNR items as `RCH` / `BND`):
  - free inputs at `-inst_top`, `stopat`, black boxes (their internal items are not analysed).
- Over-constraint check: if a constraint makes a large share of items UNR (compare runs with and without it, or use `unr_reason.txt` "Propagated assume" causes), re-validate it with the spec owner.
- Black-box / resilient compilation: check the elaboration "Resilient Compilation Summary" (D1); items in removed code are not proven unreachable.
- Coverage-model match: UNR DB and sim DB from the same RTL, defines, parameters and ccf (D1 Assumptions); otherwise refinements may become invalid (D7 "Handling Invalid Refinement Rules").

## 5. Exclude Reviewed Items (per item, with comment)

```
# IMC script: <results>/imc_unr_exclude.cmd  (run after the merge is loaded)
# Every line = one reviewed row of unr_review.csv; comment carries UNR_ID + reason + spec ref
exclude -inst <tb_top>.<inst>.<sub> -block <n> -unr -comment "<UNR_ID>: <C1..C3> <reason> (spec §<x.y>)"
exclude -inst <tb_top>.<inst>.<sub> -expression <id> -unr -comment "<UNR_ID>: <reason>"
exclude -inst <tb_top>.<inst>.<sub> -toggle <sig>\[<bit>.rise\] -unr -comment "<UNR_ID>: <reason>"
# fsm / functional items: exclude by item in the IMC GUI (Exclude button / RMB Exclude, D1) with a comment
save -refinement <results>/<ip>_<cfg>_unr.vRefine
```

- `-unr` excludes the selected objects only if they are marked unreachable (D1/D7).
- Toggle: a bit is excluded only if both rise and fall are UNR; otherwise only the UNR transition (D7).
- Forbidden without a completed review: `exclude -inst *... -metrics block:expression:toggle -unr`, `exclude -inst <inst> -unr` (D1: "before you exclude all, analyze each one").
- `check_unr -reason` `.cmd` (App. A): contains `load`, `exclude ... -comment "Unreachable Cause: ..."`, `save -refinement`; use it only for rows already reviewed — edit out the rest before `imc -exec`.
- `-comment` exists in the `exclude` syntax (D7); IMC can also prompt for comments ("Add exclude comment", D7).

## 6. Reports

```
# <results>/imc_unr_report.cmd — after loading merge + refinement
load -refinement <results>/<ip>_<cfg>_unr.vRefine
report_metrics -out <results>/unr_cov_report -overwrite -detail -inst *...
report_metrics -out <results>/unr_cov_excl -overwrite -detail -excludes -exclComments -inst *...
```

- `report_metrics` options from D7 syntax; `-exclComments` / `-excludes` apply per D7 colour notes (JSON vs old HTML) — check the generated report.
- Text alternative: `report -detail -excludes -metrics block -inst <inst>` (D7 examples); `report ... -unr` lists unreachable items (D7 `report` option list).
- Record before/after coverage numbers (D6 example: 55.39 % → 56.13 % after excluding 39 UNR items).

## 7. Apply the Refinement in Later Sim Merges

- adsim: `COVERAGE_REFINE_FILE : <path>/<ip>_<cfg>_unr.vRefine` (D8; global only; Xcelium only; kit uses the `NC_` prefixed form).
- IMC: `load -refinement <f1>,<f2>` (D7).
- Next UNR run: pass the reviewed refinement with `-load_refinement` so already-refined holes are not re-analysed (D1).
- Re-validate the refinement after any RTL, parameter, define or ccf change.
